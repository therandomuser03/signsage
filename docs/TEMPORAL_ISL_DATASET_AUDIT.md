# Temporal ISL Dataset & Model Feasibility Audit

Audit date: 2026-10-27. Scope: audit only — no training, no downloads, no model promotion changes, no dataset extraction. Source of truth: actual repository state (`docs/`, `research/`, `backend/app/ml/`, `data/`, dataset archive listings).

## 1. Existing baseline (verified from repository state)

### 1.1 What works today (verified, not assumed)

- **Static alphabet CNN** (`research/image_classification/artifacts/alphabet/model.pt` + `labels.json`): 26 ISL letters (A–Z), RealSign CC0-1.0 dataset. Verified endpoint (`POST /api/v1/classification/image`, `task=alphabet`) returns structured response (`label`, `confidence`, `accepted`, `reason`, `model_version=signsage-image-alphabet`) with actual CNN inference. Real dataset fixture (`test.npz` image 0, label index 0 = `A`) classifies with `confidence=1.0`, `accepted=true`. Frontend `TranslatePage` displays the result honestly (no fabricated translation).
- **Isolated-word pilot** (`backend/models/isl_bundle/`, `SIGNSAGE_ALLOW_UNPROMOTED_DEV=true`): 6 ISL words (friend, hello, hospital, market, school, thank you) from `vidit031/isl-isolated-40words` INCLUDE subset (122 accepted CC-BY-4.0 clips, revision `255ce7fd`). Measured: accuracy 61.1%, macro recall 61.1%, inference ~2 ms/sample CPU (`docs/ISOLATED_ISL_RECOVERY_AUDIT.md`). NOT promoted — below 80/80/60 bar, not signer-independent.
- **Backend health/capabilities/models endpoints**: verified reachable (`GET /api/v1/health` 200, `GET /api/v1/capabilities` reports `heuristic-fallback` or `isolated-word` source, `GET /api/v1/models` shows `promoted=false`).
- **WebSocket transport** (`/ws/translate`): bounded reconnect (5 attempts), `MODEL_UNAVAILABLE` returned honestly when `SIGNSAGE_MODEL_PROMOTED=false` (verified in Playwright E2E suite, 7 pass, 15.4s).
- **Playwright E2E verification** (completed in previous session, preserved): `frontend/playwright.config.ts` uses `webServer` array (backend `:8000` + preview `:4173`); `frontend/e2e/image-classify.spec.ts` includes real dataset fixture test, rejected-prediction test (`min_confidence=0.99`), invalid-image 422 test, and full-UI-verification test.

### 1.2 What does NOT work (verified, with evidence)

- **Continuous sign-to-text translation (`/ws/translate`)**: `SIGNSAGE_MODEL_PROMOTED=false`. The promoted gate is intentionally closed.
- **Transformer checkpoint 352868924 (`signsage_transformer_full.pt`)**: NO-GO (`WER 1.0046`, `BLEU 0.24`, `ROUGE-L 0.089`, `exact_match 0.0`, `output_diversity 0.99%`, `top_prediction_freq 0.4484` — `research/evaluation/reports/352868924/evaluation_results.json`). Trained on synthetic iSign text→pose data (not real ISL video), so it cannot be recovered for ISL recognition. Loadable (`model_check.py` verifies structure) but never promoted.
- **T5 POC (`t5-small-motion`)**: NO-GO (`exact_match 0/1888`, `WER ~1.0`, `BLEU 0` — `docs/EXTERNAL_EVALUATION.md` §2; `t5_poc_gate` gate fails with synthetic-gate `WIRING-FAIL` — `research/evaluation/t5_poc_gate/gate_report.json`). Tokenizer vocab mismatch (`SP-16k` serving vs `t5-small` 32k) is architectural, not a bug.
- **Sign→Text V2 (`research/training/READINESS.md`)**: NO training started. Config defined (pre-norm d256/4L, SP-16k, ≤12ep, diversity + overfit gates) but no checkpoint exists. No temporal/continuous dataset configured for this path.
- **No promoted model exists** (`docs/STATUS_AND_ROADMAP.md` §1, §4, `docs/DATA_AND_MODEL.md` §5). The only servable ML model is the static image classifier (`alphabet` only; `word` model exists at `research/image_classification/artifacts/words/model.pt` but accuracy 19.0% — unpromoted, never deployed).

### 1.4 Difference between task levels (evidence-backed, not interchangeable)

- **Static alphabet classification** (`alphabet` CNN): one image `(3,64,64)` → one letter. Verified endpoint works. Independent of continuous pipeline.
- **Isolated sign recognition** (`isolated-word` pilot): `(T,543,3)` sequence → one of 6 words. Measured 61.1% accuracy. Not sentence-level; each inference is a single gloss, not a sequence of glosses or a sentence.
- **Continuous sign recognition** (`/ws/translate` stream): `(T,543,3)` → interim `final:false` + final `final:true`. The backend supports this transport but has no promoted model. The 352868924 checkpoint does not work (`WER 1.005`). The isolated-word adapter handles single-word final results (`hello`), not multi-gloss sequences or English sentences.
- **Gloss-to-text / sentence translation**: Not present. There is no gloss vocabulary mapped to English sentences in the serving pipeline. The 14 `sign_vocabulary.json` IDs (`docs/DATA_AND_MODEL.md` §4) are EN→ISL generation labels (avatar gloss), not recognition labels. The isolated-word pilot vocabulary (6 words) has no sentence-level mapping.
- **Direct video-to-English translation** (`video → English sentence`): Not present. No video input endpoint exists (only landmark WebSocket); no video-based model is loaded; no sentence-level dataset is configured for training; no sentence-level evaluation metric (WER/BLEU/ROUGE-L) is computed for any promoted model (only broken 352868924 reports these).

**Critical evidence gap**: There is NO dataset configured or available locally that contains continuous ISL video with aligned English sentence translations. The only dataset artifacts (`research/image_classification/artifacts/alphabet/`, `words/`) are static image datasets (64×64 RGB). The `iSign` dataset (`docs/DATA_AND_MODEL.md` §1) has 127,237 rows (`uid,text`) with no per-segment timing, no video-level sentence annotations confirmed as usable for continuous recognition, and no signer-independent split verified (`video_id` split only). The `subset6.csv` manifest (`data/manifests/subset6.csv`) has 75 rows (6 classes) from the isolated-word pilot, not sentence-level continuous data.

### 2.1 Key evidence gaps (explicit, not filled with guesses)

- **No continuous sentence-level dataset with verified temporal sign-boundary annotations is present locally.** The `iSign` dataset (`docs/DATA_AND_MODEL.md` §1) has continuous `.pose` sequences (`video_id` split) but no verified per-sign temporal annotations (only `uid` → `text` mapping, no frame-level gloss alignment). The `subset6.csv` manifest (`75` rows, `uid` format `video_id--seq`) suggests a very small isolated-word subset derived from iSign, not a full temporal sentence dataset.
- **No external continuous ISL video dataset was downloaded or audited in detail.** The repository references `iSign` (gated HF), `INCLUDE` (video clips, 122 downloaded for audit), `CISLR` (referenced in audit), and `ISLRTC` (PDF + chart only — no video dataset). No `dataset_manifest.json` for a temporal sentence-level dataset exists (`data/manifests/` only has `subset6.csv` and no temporal manifest).
- **No video-level sentence-aligned dataset with signer-independent split is verified.** The `audit_dataset.py` (`research/experiments/audit_dataset.py`) verifies dataset integrity (checksums, split rules, junk text filtering) but does not verify temporal sign-boundary annotations or signer-independent evaluation (`docs/ISOLATED_ISL_RECOVERY_AUDIT.md` §2: "Reproducible 86/18/18 split groups matching recording IDs together and has no recording-ID overlap across partitions, but cannot establish signer-independent generalization").
- **The `subset6.csv` manifest does not match the 6-word pilot vocabulary** (`friend`, `hello`, `hospital`, `market`, `school`, `thank you`). The manifest contains words like `three`, `one`, `two`, `music`, `water`, `you`. This discrepancy is noted; it may indicate the manifest references a different experiment or dataset version, not the `isl-isolated-40words` pilot.

## 6. Recommended roadmap (evidence-backed, not speculative)

Based on all verified evidence above: no promoted temporal/sentence-level model exists; no suitable temporal dataset with verified annotations exists locally; the only verified ML service (`alphabet` CNN) is static-only; the `iSign` dataset (continuous poses) is the only continuous data source but requires significant new work (temporal annotations, model training, evaluation framework) before sentence-level translation is feasible.

### 6.1 Immediate next milestone (smallest credible step — aligned with `SIGN_RECOGNITION_EXPANSION_PLAN.md`)

**Target**: A bounded, evaluated isolated-word temporal prototype (not sentence translation) using the verified `iSign` dataset reference and the existing `ContinuousSignPipeline` transport mechanism.

**Explicit non-goals** (must not claim): sentence-level English translation (`docs/DATA_AND_MODEL.md` §4: no sentence-level vocabulary or grammar mapping exists); continuous multi-word recognition beyond single-gloss output; signer-independent evaluation (metadata does not verify signers — `docs/ISOLATED_ISL_RECOVERY_AUDIT.md` §2); promotion of any new model (`SIGNSAGE_MODEL_PROMOTED` stays `false` until §7 criteria met — `docs/SIGN_RECOGNITION_EXPANSION_PLAN.md` §7).

**Required dataset**: The `iSign` dataset (`docs/DATA_AND_MODEL.md` §1; `docs/ISOLATED_ISL_RECOVERY_AUDIT.md` §2) — but only a very small, bounded subset (`subset6.csv` reference: 75 rows; `SIGN_RECOGNITION_EXPANSION_PLAN.md` §3 proposes a 6-class subset from the 122 INCLUDE clips, or a 6-word subset from the full iSign dataset, with strict split rules by `video_id` and recording-ID grouping). The full iSign dataset download (158+ GB `.pose` archive) is NOT required for this milestone and MUST NOT be performed (task constraint: no large dataset downloads). Only the subset CSV (`subset6.csv`) and any pre-existing local pose references (`staging_kaggle_results/isign/iSign_v1.1.csv` — 9.4 MB, already present; no `.pose` archive download needed) are used.

**Reusable components** (`SIGN_RECOGNITION_EXPANSION_PLAN.md` §3; `docs/DEVELOPMENT.md` §2; `docs/DATA_AND_MODEL.md` §2; verified in Playwright E2E and backend tests):
